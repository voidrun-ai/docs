# TypeScript SDK (`@voidrun/sdk`)

The official **Node.js** client for VoidRun: ESM-first, TypeScript types generated from OpenAPI, and API names aligned with the [Python SDK](/sdks/python). Use this page for a structured reference; the [package README](https://www.npmjs.com/package/@voidrun/sdk) and repo `examples/` stay the source for exhaustive snippets.

## Requirements and install

- **Node.js** 18+ (ESM); Node 20+ recommended for `tsx` examples  
- **TypeScript** 5.x when compiling from source

```bash
npm install @voidrun/sdk
```

## Configuration

`VoidRun` **requires an API key**. If you omit `apiKey`, the client reads **`process.env.VR_API_KEY`** (empty → throws).

**Base URL** defaults to the packaged **`BASE_PATH`** (same host as OpenAPI **`servers`**). You override it only for **self-hosted** deployments: see below.

```typescript
import { VoidRun } from '@voidrun/sdk';

const vr = new VoidRun({
  apiKey: process.env.VR_API_KEY!,
});
```

| Variable | Role |
|----------|------|
| `VR_API_KEY` | API key when not passed to the constructor |
| `VR_API_URL` | *(Self-hosted only.)* Overrides the packaged API base URL |

<Note>
Hosted VoidRun: you only need **`VR_API_KEY`**. For **self-managed** APIs, set **`VR_API_URL`** (or **`baseUrl`**) to your deployment’s root (include `/api` if that is how the server is mounted). See [Self-hosted deployments](/advanced/self-hosted).
</Note>

### Create sandbox (`createSandbox`)

`vr.createSandbox(options)` calls **`POST /sandboxes`**. The request body matches OpenAPI **`CreateSandboxRequest`** (see [API Reference](/sdks/overview#interactive-api-reference) → **Sandboxes** → **Create sandbox**).

```typescript
const sandbox = await vr.createSandbox({
  name: 'my-job',
  image: 'code',
  cpu: 2,
  mem: 2048,
  envVars: { NODE_ENV: 'production' },
  labels: { env: 'prod', team: 'api' },
  autoSleep: true,
  sync: true,
});
```

#### Options

| Option | Type | Required | Default | Description |
|--------|------|----------|---------|-------------|
| `name` | `string` | No* | `sdbx-<timestamp>` | DNS-1123 subdomain label for the VM. The SDK generates a name if you omit it; the API still requires a name on the wire. |
| `image` | `string` | No | `code` | Image id in `name` or `name:ver` form. On hosted VoidRun, common system images are **`code`**, **`docker-lite`**, **`max`**, and **`docker`** — see [System images](/environments/custom-images#system-images). |
| `cpu` | `number` | No | `1` | vCPU count. API allows **1–8**. |
| `mem` | `number` | No | `1024` | Memory in **MiB**. API allows **1024–16384**. |
| `orgId` | `string` | No | From API key | Organization that owns the sandbox. See [Organization and user identity](#organization-and-user-identity) below. |
| `userId` | `string` | No | From API key | User attributed as the sandbox creator. See [Organization and user identity](#organization-and-user-identity) below. |
| `sync` | `boolean` | No | `true` | When `true`, creation blocks until the guest agent passes a fast readiness check (~2s timeout). Set `false` only if you intentionally poll readiness yourself. |
| `envVars` | `Record<string, string>` | No | — | Environment variables injected into the sandbox (visible to **`exec`**, **`runCode`**, and shells). Prefer this over putting secrets in command strings. |
| `autoSleep` | `boolean` | No | — | When `true`, the platform **auto-snapshots** the VM after idle time and wakes it on the next request. See [Sandbox lifecycle](/core-concepts/lifecycle). |
| `region` | `string` | No | — | Target region (for example `eu`) when your account supports regional placement. |
| `publishPorts` | `number[]` | No | — | TCP ports to expose as public HTTPS URLs (up to 4). See [Public URLs](/networking/public-urls). |
| `labels` | `Record<string, string>` | No | — | Immutable metadata set at creation. Up to **5** labels; keys and values are at most **20** characters. Keys must use lowercase letters or numbers, may contain `-` or `_`, and must start and end with a letter or number. Neither keys nor values may contain `,` or `=`. |
| `refId` | `string` | No | — | External reference id for your own tracking (billing, tickets, workflow run id). |

\* **`name`** is required on the REST contract; the TypeScript client supplies a generated name when you omit it.

#### Organization and user identity

Every **`POST /sandboxes`** call is authenticated with **`X-API-Key`**. The platform resolves **organization** and **user** from that key:

- **`orgId`** — the organization the API key belongs to.
- **`userId`** — the user associated with the key (typically the user who created the key).

**When you omit `orgId` and `userId`** (recommended), the API uses those resolved values. The TypeScript client sends empty strings by default, which the service treats as “use the key’s org and user.”

**When you pass `orgId` and/or `userId`**, the API validates that:

1. The API key is authorized for the given **`orgId`** (the key must belong to that organization).
2. The given **`userId`** is related to that organization (owner or member).

If the key, user, and org are not consistent, the request fails (for example **403 Forbidden**). You cannot create a sandbox under another org or as an unrelated user.

<Note>
The VoidRun MCP tool **`create_sandbox`** accepts the same **`CreateSandboxRequest`** fields as REST and the SDKs (including **`mem`**, **`orgId`**, **`userId`**, **`envVars`**, **`autoSleep`**, **`sync`**, **`region`**, **`refId`**). See [VoidRun MCP](/integrations/mcp).
</Note>

Returns a **`VRSandbox`** instance. Use **`sandbox.remove()`** (or **`vr.removeSandbox(id)`**) when you are done. For long CI-style jobs that must not idle-pause, pass **`autoSleep: false`** (see [GitHub Actions example](/examples/github-actions)).

## Client: `VoidRun`

| Method | Returns |
|--------|---------|
| `createSandbox(options)` | `VRSandbox` |
| `getSandbox(id)` | `VRSandbox` |
| `listSandboxes({ page?, limit?, labels? })` | `{ sandboxes, meta }` |
| `removeSandbox(id)` | `void` (after API delete) |

**Pagination `meta`:** `total`, `page`, `limit`, `totalPages` (camelCase).

```typescript
const { sandboxes, meta } = await vr.listSandboxes({
  page: 1,
  limit: 50,
  labels: { env: 'prod', team: 'api' },
});
console.log(meta.total, meta.totalPages);
```

Label filters use AND semantics: a sandbox must match every supplied pair, but
may contain additional labels.

## Sandbox lifecycle

On the sandbox instance:

- `sleep()` — snapshot the VM (status becomes `snapshotted`)
- `wake()` — restore from snapshot back to `running`
- `start()` — recovery boot for `snapshotted` / `killed` / `error` sandboxes
- `stop()` / `pause()` — aliases of `sleep()` (the API has no `/stop` or `/pause` route)
- `resume()` — alias of `wake()`
- `remove()` — delete the sandbox on the API
- `info()` — returns `Promise<this>` (refreshed view)

Any API call against a `snapshotted` sandbox transparently wakes it, so you usually don't need to call `wake()` yourself. See [Sandbox lifecycle](/core-concepts/lifecycle) for the full state machine.

```typescript
const sandbox = await vr.createSandbox({ name: 'demo', cpu: 2, mem: 2048 });
await sandbox.exec({ command: 'echo ok' });
await sandbox.remove();
```

## Public URLs

Publish ports at create time or update them later, then fetch the public URLs from the sandbox instance:

```typescript
const sandbox = await vr.createSandbox({
  name: 'preview',
  cpu: 2,
  mem: 2048,
  publishPorts: [8080],
});

const urls = await sandbox.getPublicUrls();
// [{ port: 8080, url: 'https://s...-8080.sb.void-run.com' }]

const preview = await sandbox.getPublicUrl(8080);
console.log(preview?.url);
```

See [Public URLs](/networking/public-urls) for the full behaviour, including cold-wake on the first request.

## Shell execution (`exec`)

Non-streaming **`exec`** returns an **`ExecResponse`**. Read stdout/stderr/exit code from **`result.data`** (`ExecResponseData`):

```typescript
const result = await sandbox.exec({ command: 'uname -a' });
console.log(result.data?.stdout);
console.log(result.data?.stderr);
console.log(result.data?.exitCode);
```

**Options** on the request object: `command`, `cwd`, `env`, `timeout` (seconds).

### Streaming

Pass a **second argument** with handlers, or use **`execStream`**:

```typescript
await sandbox.exec(
  { command: 'for i in 1 2 3; do echo $i; sleep 1; done' },
  {
    onStdout: (chunk) => console.log('out:', chunk),
    onStderr: (chunk) => console.error('err:', chunk),
    onExit: (r) => console.log('exit', r),
    onError: (e) => console.error(e),
    signal: abortController.signal,
  },
);
```

## Code interpreter (`runCode`)

**`runCode`** returns **`CodeExecutionResult`**: fields live at the **top level** (no `.data` wrapper):

| Field | Meaning |
|-------|---------|
| `success` | Overall success |
| `stdout` / `stderr` | Combined streams |
| `exitCode` | Process exit code |
| `results` | Parsed output when applicable |
| `logs` | e.g. per-line `stdout` / `stderr` arrays |

```typescript
const r = await sandbox.runCode('print(2 + 2)', { language: 'python' });
console.log(r.stdout.trim(), r.success);
```

**Languages** commonly supported: `python`, `javascript`, `typescript`, `node`, `bash`, `sh` (confirm on your deployment).

Streaming callbacks (`onStdout`, `onStderr`, …) are supported via the options object.

## Background commands

**`sandbox.commands`** uses **positional** arguments for `run`:

```typescript
const run = await sandbox.commands.run(
  'npm run dev',
  { NODE_ENV: 'development' }, // env (optional)
  '/app',                        // cwd (optional)
  0,                             // timeout; 0 = none
);
console.log(run.pid);

const { processes } = await sandbox.commands.list();
await sandbox.commands.wait(run.pid);
await sandbox.commands.kill(run.pid);
```

**`connect(pid, handlers)`** attaches to a process stream (`onStdout`, `onStderr`, `onExit`, `onError`).

See [Background commands](/core-concepts/background-commands) for REST paths and concepts.

## File system (`sandbox.fs`)

High-level operations include:

- **Write:** `createFile`, `uploadFile`, `uploadFileStream`
- **Read:** `downloadFile`, `downloadFileStream`, `headTail`
- **Manage:** `deleteFile`, `listFiles`, `statFile`, `createDirectory`, `moveFile`, `copyFile`, `changePermissions`
- **Search / size:** `searchFiles`, `folderSize`
- **Archives:** `compressFile`, `extractArchive`

List responses often expose entries on **`result.data?.files`** (check types for your SDK version).

```typescript
await sandbox.fs.uploadFile('/tmp/hello.txt', 'hello');
const buf = await sandbox.fs.downloadFile('/tmp/hello.txt');
```

## File watching

```typescript
const watcher = await sandbox.fs.watch('/app', {
  recursive: true,
  onEvent: (ev) => console.log(ev.path, ev.type),
  onError: (err) => console.error(err),
  onClose: () => console.log('closed'),
});
watcher.close();
```

See [File watching](/core-concepts/file-watching) for the HTTP + WebSocket flow.

## PTY (`sandbox.pty`)

- **Ephemeral:** `connect({ onData, onError })`: temporary shell; `sendInput`, `close`.
- **Persistent:** `createSession()` → use returned **`sessionId`** with `connect({ sessionId, … })`; sessions survive disconnect until deleted.
- **Helpers:** `runCommand(cmd, { timeout, prompt })`, `resize(cols, rows)`, `list()`, `deleteSession(id)`.

See [PTY](/core-concepts/pty) and the npm README for full examples.

## Error handling

API failures surface as thrown errors. Response bodies often include **`error`** and **`details`**: log both when debugging. The SDK may concatenate them into the error message.

## Sub-clients summary

| Property | Purpose |
|----------|---------|
| `sandbox.fs` | Files and directories |
| `sandbox.pty` | Interactive terminals |
| `sandbox.interpreter` | Same family of helpers as `runCode` |
| `sandbox.commands` | Background processes |
