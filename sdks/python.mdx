# Python SDK (`voidrun`)

The official **Python 3.9+** client for VoidRun: Pydantic models, generated OpenAPI client under `voidrun.api_client`, and high-level names aligned with the [TypeScript SDK](/sdks/typescript). This page is a structured reference; the [PyPI readme](https://pypi.org/project/voidrun/) and repo `examples/` contain the full script catalog.

## Requirements and install

- **Python 3.9+**  
- Dependencies include **httpx**, **Pydantic v2**, **websockets**, etc. (see `pyproject.toml` in the repo)

```bash
pip install voidrun
```

Editable install for development:

```bash
cd py-sdk && pip install -e .
```

## Configuration

You need an **API key**. The **API base URL** defaults to the same hosted endpoint as the TypeScript SDK (**`DEFAULT_API_BASE_URL`**, aligned with OpenAPI **`servers`**). You set **`VR_API_URL`** / **`API_URL`** or **`base_url=`** only when you use a **self-hosted** API: see [Self-hosted deployments](/advanced/self-hosted).

```python
from voidrun import VoidRun

vr = VoidRun(
    api_key="...",  # optional if VR_API_KEY or API_KEY is set
)
```

| Variable | Role |
|----------|------|
| `VR_API_KEY` or `API_KEY` | API key |
| `VR_API_URL` or `API_URL` | *(Self-hosted only.)* Overrides the default API base URL |
| `VR_ORG_ID` | Optional default org id |

### Exported defaults

Aligned with `@voidrun/sdk`:

| Constant | Value | Meaning |
|----------|-------|---------|
| `DEFAULT_API_BASE_URL` | `https://platform.void-run.com/api` | Default API host (strip trailing slash in client) |
| `DEFAULT_SANDBOX_IMAGE` | `"code"` | Default `image` when creating a sandbox |
| `DEFAULT_SANDBOX_CPU` | `1` | Default CPU count |
| `DEFAULT_SANDBOX_MEM` | `1024` | Default memory (MB) |

```python
from voidrun import (
    DEFAULT_API_BASE_URL,
    DEFAULT_SANDBOX_IMAGE,
    DEFAULT_SANDBOX_CPU,
    DEFAULT_SANDBOX_MEM,
)
```

### Create sandbox (`create_sandbox`)

`vr.create_sandbox(...)` (and **`await vr.create_sandbox(...)`** on **`AsyncVoidRun`**) call **`POST /sandboxes`**. The body matches OpenAPI **`CreateSandboxRequest`**. See [API Reference](/sdks/overview#interactive-api-reference) → **Sandboxes** → **Create sandbox**.

Use **snake_case** keyword arguments. The client also accepts **camelCase** aliases where noted (same as the TypeScript SDK field names).

```python
sandbox = vr.create_sandbox(
    name="my-job",
    image="code",
    cpu=2,
    mem=2048,
    env_vars={"PYTHONUNBUFFERED": "1"},
    labels={"env": "prod", "team": "api"},
    auto_sleep=True,
    sync=True,
)
```

#### Options

| Option (Python) | Alias | Type | Required | Default | Description |
|-----------------|-------|------|----------|---------|-------------|
| `name` | — | `str` | No* | `sdbx-<timestamp>` | DNS-1123 subdomain label for the VM. The client generates a name if omitted. |
| `image` | — | `str` | No | `"code"` (`DEFAULT_SANDBOX_IMAGE`) | Image id in `name` or `name:ver` form. Hosted images: **`code`**, **`max`**, **`docker`** — [System images](/environments/custom-images#system-images). |
| `cpu` | — | `int` | No | `1` | vCPU count. API allows **1–8**. |
| `mem` | — | `int` | No | `1024` | Memory in **MiB**. API allows **1024–16384**. |
| `org_id` | `orgId` | `str` | No | API key / `VR_ORG_ID` | Organization that owns the sandbox. See [Organization and user identity](#organization-and-user-identity) below. |
| `user_id` | `userId` | `str` | No | From API key | User attributed as the sandbox creator. See [Organization and user identity](#organization-and-user-identity) below. |
| `sync` | — | `bool` | No | `True` | Block until the guest agent is ready (~2s check) when `True`. |
| `env_vars` | `envVars` | `dict[str, str]` | No | — | Environment variables for the sandbox VM. |
| `auto_sleep` | `autoSleep` | `bool` | No | — | Enable platform **auto-snapshot** after idle; the sandbox wakes on the next request. See [Sandbox lifecycle](/core-concepts/lifecycle). |
| `region` | — | `str` | No | — | Target region when supported by your account. |
| `publish_ports` | `publishPorts` | `list[int]` | No | — | TCP ports to expose as public HTTPS URLs (up to 4). See [Public URLs](/networking/public-urls). |
| `labels` | — | `dict[str, str]` | No | — | Immutable metadata set at creation. Up to **5** labels; keys and values are at most **20** characters. Keys must use lowercase letters or numbers, may contain `-` or `_`, and must start and end with a letter or number. Neither keys nor values may contain `,` or `=`. |
| `ref_id` | `refId` | `str` | No | — | External reference id for your workflows. |

\* **`name`** is required on the REST contract; the Python client supplies a generated name when you omit it.

#### Organization and user identity

Every **`POST /sandboxes`** call uses **`X-API-Key`** (or **`VR_API_KEY`** / **`API_KEY`** in the client). The platform resolves **organization** and **user** from that key:

- **`orgId`** — the organization the API key belongs to.
- **`userId`** — the user associated with the key (typically the key creator).

**When you omit `org_id` and `user_id`** (recommended), the API uses the org and user from the key. If you set **`VR_ORG_ID`** on the client, Python may send that as **`org_id`** when you do not pass one explicitly; it must still match the key’s organization.

**When you pass `org_id` / `user_id`** (or **`orgId`** / **`userId`**), the API validates that:

1. The API key is authorized for the given organization.
2. The given user is an owner or member of that organization.

Mismatched key, user, and org return an error (for example **403 Forbidden**).

<Note>
The VoidRun MCP tool **`create_sandbox`** uses the same **`CreateSandboxRequest`** fields as REST and this SDK. See [VoidRun MCP](/integrations/mcp).
</Note>

**Context managers** call **`remove()`** / **`remove_async()`** on exit:

```python
with vr.create_sandbox(name="demo", mem=2048) as sandbox:
    sandbox.exec("echo ok")
```

## Clients: `VoidRun` and `AsyncVoidRun`

| Method | Sync | Async |
|--------|------|-------|
| Create sandbox | `create_sandbox(...)` | `await create_sandbox(...)` |
| Get sandbox | `get_sandbox(id)` | `await get_sandbox(id)` |
| List sandboxes | `list_sandboxes(page=, limit=, labels=)` | `await list_sandboxes(...)` |
| Remove by id | `remove_sandbox(id)` | `await remove_sandbox(id)` |

**`list_sandboxes`** returns **`ListSandboxesResult`**:

- **`.sandboxes`**: list of **`Sandbox`** instances  
- **`.meta`**: **`ListSandboxesMeta`**: `total`, `page`, `limit`, `total_pages` (snake_case)

Pass `labels={"env": "prod", "team": "api"}` to match sandboxes containing
every supplied pair (AND semantics). Matching sandboxes may have additional
labels.

`AsyncVoidRun` supports **`async with`** and **`aclose()`** for cleanup (including the thread pool used for API calls).

### Context managers

- **Sync:** `with vr.create_sandbox(...) as sandbox:` → **`remove()`** on exit (see [Create sandbox](#create-sandbox-create_sandbox) above).  
- **Async:** `async with await vr.create_sandbox(...) as sandbox:` → **`remove_async()`** on exit  

## Sandbox lifecycle

On **`Sandbox`**:

- **`sleep()`** / **`sleep_async()`** — snapshot the VM (status becomes `snapshotted`)
- **`wake()`** / **`wake_async()`** — restore from snapshot back to `running`
- **`start()`** / **`start_async()`** — recovery boot for `snapshotted` / `killed` / `error` sandboxes
- **`stop()`** / **`pause()`** — aliases of `sleep()`; async variants alias `sleep_async()`
- **`resume()`** — alias of `wake()`; `resume_async()` aliases `wake_async()`
- **`remove()`** / **`remove_async()`** — delete the sandbox on the API
- **`info()`** — returns `self` (refreshed view)

Deprecated aliases **`delete`** / **`delete_async`** map to remove.

Any API call against a `snapshotted` sandbox transparently wakes it, so you usually don't need to call **`wake()`** yourself. See [Sandbox lifecycle](/core-concepts/lifecycle) for the full state machine.

Notable attributes include **`id`**, **`name`**, **`cpu`**, **`mem`**, **`status`**, **`image`**, **`env_vars`**, **`region`**, **`org_id`**, and immutable **`labels`**.

## Public URLs

Publish ports at create time (or update them later), then fetch the public URLs from the sandbox instance:

```python
sandbox = vr.create_sandbox(
    name="preview",
    cpu=2,
    mem=2048,
    publish_ports=[8080],
)

urls = sandbox.get_public_urls()
# [SandboxPublicURL(port=8080, url="https://s...-8080.sb.void-run.com")]

preview = sandbox.get_public_url(8080)
if preview is not None:
    print(preview.url)
```

**`AsyncVoidRun`** exposes **`get_public_urls_async`** and **`get_public_url_async`** on the sandbox. See [Public URLs](/networking/public-urls) for the full behaviour, including cold-wake on the first request.

## Shell execution (`exec`)

You can pass a **string**, keyword args, or a generated **`ExecRequest`**:

```python
from voidrun.api_client.models.exec_request import ExecRequest

sandbox.exec("uname -a")
sandbox.exec(command="pwd", cwd="/tmp", timeout=60)
sandbox.exec(ExecRequest(command="ls", cwd="/"))
```

**Return type:** **`VoidRunResponse[ExecResponseData]`**: the HTTP envelope is unwrapped so **`.data`** is already **`ExecResponseData`**:

```python
r = sandbox.exec('echo "hi"')
print(r.data.stdout, r.data.stderr, r.data.exit_code)
```

Use **`.data.stdout`** / **`.data.stderr`** / **`.data.exit_code`**: not **`.data.data.*`** (single `.data`).

### Streaming (`exec_stream`)

Provide **`on_stdout`**, **`on_stderr`**, **`on_exit`**, **`on_error`** for SSE-style streaming.

## Code interpreter (`run_code` / `interpreter`)

**`sandbox.run_code(code, language=..., ...)`** and **`sandbox.interpreter.run(...)`** return **`CodeExecutionResult`** directly (**no** extra `.data` wrapper):

| Field | Type | Notes |
|-------|------|--------|
| `success` | `bool` | Derived from exit behavior |
| `stdout` / `stderr` | `str` | Combined streams |
| `exit_code` | `int \| None` | Process exit code |
| `results` | `Any` | Parsed output when applicable |
| `error` | `str \| None` | Error hint |
| `logs` | `dict` | Often line lists per stream |

```python
result = sandbox.run_code("print(2 + 2)", language="python")
print(result.stdout.strip(), result.success)
```

**Languages** (typical): `python`, `javascript`, `typescript`, `node`, `bash`, `sh`: confirm on your deployment.

## Background commands

```python
run_result = sandbox.commands.run(
    "sleep 5 && echo done",
    {"DEBUG": "true"},  # env (optional)
    "/tmp",              # cwd (optional)
    0,                   # timeout; 0 = none
)
pid = run_result.data.pid

sandbox.commands.list()       # .data is the process list payload
sandbox.commands.wait(pid)
sandbox.commands.kill(pid)
sandbox.commands.connect(pid, on_stdout=..., on_stderr=..., on_exit=...)
```

See [Background commands](/core-concepts/background-commands).

## File system (`sandbox.fs`)

Snake_case methods mirror the TS surface, for example:

- **Write:** `create_file`, `upload_file`, `upload_file_from_path`  
- **Read:** `download_file`  
- **Manage:** `delete_file`, `list_files`, `stat_file`, `create_directory`, `move_file`, `copy_file`, `change_permissions`  
- **Utilities:** `head_tail`, `search_files`, `disk_usage`  
- **Archives:** `compress_file`, `extract_archive`  

```python
sandbox.fs.upload_file("/tmp/hello.txt", "Hello")
data = sandbox.fs.download_file("/tmp/hello.txt")
listing = sandbox.fs.list_files("/tmp")
files = listing.data
```

## File watching (async)

**`sandbox.fs.watch`** is **async**: use **`AsyncVoidRun`** and **`await sandbox.fs.watch(...)`**:

```python
watcher = await sandbox.fs.watch(
    "/app",
    recursive=True,
    on_event=lambda evt: print(evt.get("path"), evt.get("type")),
    on_error=lambda err: print("watch error:", err),
)
# ...
watcher.close()
```

See [File watching](/core-concepts/file-watching).

## PTY (`sandbox.pty`)

- **`await connect(...)`** (async): ephemeral or persistent (`session_id=`).  
- **`create_session()`** / **`create_session_async()`**: persistent session; read **`session_id`** from the nested response model (typically **`resp.data.data.session_id`** on the Pydantic envelope; inspect types if your spec differs).  
- **`run_command`**, **`resize`**, **`list`**, **`delete_session`**.

Full patterns: [PTY](/core-concepts/pty) and the package README.

## Naming: snake_case and camelCase

Beyond **`create_sandbox`**, most Python methods use **snake_case**. A few kwargs accept **camelCase** aliases for parity with TypeScript (documented per method in the PyPI readme).

## Error handling

Failures raise **`ApiException`** (and related) from **`voidrun.api_client.rest`** with HTTP status and body. Parse **`error`** and **`details`** from JSON bodies when present.

```python
from voidrun.api_client.rest import ApiException

try:
    vr.get_sandbox("nonexistent-id")
except ApiException as e:
    print(e.status, e.body)
```

## Runnable examples and tests

From the **`py-sdk`** repo root (with **`PYTHONPATH`** set, e.g. to the package root):

```bash
export VR_API_KEY="..."

./scripts/run_all_examples.sh   # exits 1 if any script fails
python3 examples/sync_usage.py
```

**Tests:** `pytest tests/` or `hatch run test`.

## OpenAPI regeneration

Regenerate **`voidrun.api_client`** when **`voidrun/openapi.yml`** changes. After regen, confirm **sandbox `status`** enum values still match the live server: **`running`**, **`snapshotted`**, **`error`**, **`killed`**, **`deleted`**.
